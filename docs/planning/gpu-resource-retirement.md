# GPU resource ownership and retirement slice

Status: implemented and verified locally following Linux/Windows clear-only first light at `b7f0334`. [Evidence](../evidence/M2/gpu-resources/README.md) records four Linux configurations, strict owned analysis, real GPU roundtrips/retirement/replacement and 21 controlled failure scenarios. Windows/NVIDIA resource execution and independent/formal acceptance remain open. This is a bounded M2-B slice under the existing authorization, not M2-A/M2 acceptance or ratification of all proposed ADRs.

Use the existing one-graphics-queue/two-context policy and add pinned VMA 3.3.0 to the optional renderer graph only. This is the available stable Conan recipe and the allocator selected by the renderer specification. Standard Vulkan exposes allocation primitives, not the required suballocation/budget machinery; using VMA avoids implementing another device-memory allocator. Preserve every existing lock pin and the graphics-free CPU graph. Compile one private VMA implementation with a Vulkan 1.3 ceiling and retain its license/provenance.

The context owns allocator/registry state and all native allocations. Public buffers/images are move-only RAII values with generation-checked tickets and weak owner state, not global shared ownership of the device. Releasing a value queues its slot for retirement; no allocation can be reused until its last using submission completes. A context shutdown first proves completion, then invalidates/reclaims its resources; values that outlive it become empty and their destructors cannot dereference dead context state. Native getters are borrowed owner-thread access, not leases across close or asynchronous work. Reject foreign-context/stale resources before recording work.

Start with 64 resource records, two bounded transfer contexts and a 256 MiB live allocation admission budget, separate from WSI images and VMA reserved-block statistics. Bound individual requests, dimensions and copy ranges; report exhaustion rather than growing storage. Report live/retiring counts, allocation bytes and reserved bytes separately. Measure a repeated fixed workload's plateau rather than equating requested bytes with physical residency or imposing a universal performance claim. Keep staging and readback access explicit and reject CPU access while GPU use is pending.

Track successful resource-using queue submissions with a timeline semaphore, marking resource use only after actual submission succeeds. Current clear frames use none of these resources; future draw binding must join the tracker before native use. Poll completion to reclaim retired allocations; ordinary collection/upload/resize must not call device idle. Keep WSI presentation retirement separate. Use native Vulkan timeline waits in the resource regression to hold real GPU work pending, release owners while pending, and prove that allocations remain until completion. Always release the test gate before cleanup, including failure paths. Partial native construction and failed submission must preserve valid ownership and diagnostics.

Implement incrementally through the public resource API and a dedicated native resource probe: buffer creation/move/close invalidation first; checked writes/copies/readback and in-flight release next; images and repeated replacement/resize afterward. Keep pure admission contracts in existing native CTest targets when meaningful, not a mocked internal ownership model. Reuse the actual SDL/Vulkan/Conan graphs and existing framework. Exercise partial allocation, queue failure, capacity/range rejection and shutdown. Run Debug/Release/ASan and GCC locally, strict affected-consumer analysis, then hosted builds/tests. Extend the Windows helper only when the complete resource probe is ready, rather than requesting an owner run for each intermediate behavior.

Acceptance for this slice requires exact data after real GPU copies, deferred destruction while a timeline gate holds work pending, complete reclamation after completion, stable measured reserved/allocation bytes across repeated replacement, no validation or sanitizer diagnostics, zero device idle during normal work and actual Windows/NVIDIA execution. It does not establish cooked asset publication, shader layouts, PBR, pixel correctness, arbitrary driver recovery or formal milestone acceptance.
