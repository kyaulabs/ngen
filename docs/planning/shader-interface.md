# Shader interface slice

Status: M2-C Linux implementation verified in four configurations, including actual Intel culling/PBR fixtures. [Evidence](../evidence/M2/shader-interface/README.md). Windows/NVIDIA execution and the compiler-choice gate remain pending. Source branches from integrated foundation `e1cc4f4`. Full M2 acceptance remains open. Slang is a candidate, not an accepted production compiler until the minimum-profile gate passes.

First package one pinned offline compiler as a build-profile tool, with upstream archive hashes, notices and process-local library discovery. Conan Center currently has no matching `slang` or `shader-slang` recipe; a narrow namespaced binary-tool recipe avoids a runtime compiler dependency or another build framework. Evaluate Slang v2026.21 (upstream release 2026-11-04). Keep CPU-only dependencies unchanged.

Use a finite shader set: metallic-roughness vertex/fragment and a simple bounded sphere-culling compute entry. Fix Vulkan 1.3/SPIR-V 1.5, matrix convention, ordinary descriptors and explicit buffer layouts; do not require device addresses, bindless, FP64 or Vulkan 1.4. Compile and validate offline, retain compiler/dependent-library/source hashes and compiler reflection. Compare bindings, stages, buffer sizes/offsets and matrix layout with owning C++ contract types. No runtime shader compiler or JSON-reflection parser is needed in the game.

The initial SPIR-V 1.6 candidate compiled and passed Vulkan 1.3 semantic validation, but capability admission caught `DemoteToHelperInvocation` (5379) generated for fragment `discard`. The current Context does not enable `shaderDemoteToHelperInvocation`. Target SPIR-V 1.5 instead: the same Slang source emits baseline `OpKill`. This keeps the Vulkan 1.3 device contract unchanged rather than quietly requesting another feature. Capability admission also reproduces/rejects Float64 (10), which semantic validation alone admits.

Implement through meaningful public-interface Red/Green tests: compiled/validated artifacts and metadata first, rejection/transactional output next, then real GPU shader-module/pipeline/compute and small offscreen material output with exact or tolerance-based expectations. Reuse the existing Context, VMA implementation, native validation and CTest graphs. The implemented test-only fixture owns native allocations and proves completion before host access/reuse/teardown; it never submits Context-owned resources natively. Any shipping draw/dispatch using those resources must join their last-use tracking before native use. Do not promote this blocking fixture as the runtime renderer.

Verify Clang Debug/Release/ASan and GCC with strict affected consumers and pinned formatting. Extend the existing Windows helper once the complete candidate gate is ready, then inspect owner MSVC/clang-cl results. Record exact compiler/library hashes, SPIR-V validation, layout/compute/material results and limitations. If Slang fails the actual minimum-profile gate, investigate the concrete cause before selecting the documented GLSL/glslang replacement; do not maintain two production pipelines by default.

Integrate each verified logical PR into develop and remove its branch, then continue the cooked glTF package, fixed shadow/opaque/transparent/post/UI passes, queued inspector and required visual/performance/independent acceptance. Do not equate a compiler pass, compute result or triangle with M2 completion.
