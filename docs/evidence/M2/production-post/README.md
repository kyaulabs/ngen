# Context-owned HDR post-processing draw

Status: production offscreen post pass implemented on signed `885e3d1`; its [push workflow](https://github.com/kyaulabs/ngen/actions/runs/42279347099) passes all four jobs. **M2 remains open.** The imported ship, shadow/opaque/transparent/UI schedule, WSI resource-use integration, resident versions, inspector and final performance/platform/acceptance gates are not established by these small controls. See the [remaining runtime work](../../../planning/runtime-scene-renderer.md).

`Context::post_process` now performs a real dynamic-rendering draw from a tracked initialized HDR/color source to a distinct tracked single-mip RGBA8 target. It uses the existing two bounded resource command contexts and timeline, not the independent shader fixture's native allocations/submissions. Explicit read/write barriers and successful-submit-only layout/last-use publication retain both images through in-flight owner release. Descriptor slots are reused only after observed/host-acquired resource completion; pipeline/layout/pool/sampler ownership closes only after Context proves completion/loss. No ordinary-frame device idle or render-thread compiler/reflection/file loader is added.

Five offline entries now include the fullscreen post pair. Validated SPIR-V is embedded in an immutable generated C++ header with recorded SHA256 and exact-byte tests. Post constants match compiled C++ offsets/size through reflection. The first Slang `SV_VertexID` attempt emitted unenabled DrawParameters capability 4427; `SV_VulkanVertexID` uses the baseline index semantics without widening the allowed capability set. A real public negative control keeps that distinction enforced. Shader compilation, validation and all five reflections remain offline; Windows metadata capture now retains the post pair too.

Actual Iris Xe runs in Clang Debug/Release/ASan+UBSan+leak and GCC Debug verify four asymmetric HDR pixels against analytic tone mapping, half exposure and exactly one hardware sRGB encoding. Eight softened diagonal pixels and unchanged flat regions exercise the spatial AA toggle; this is a bounded FXAA-style filter, not temporal AA or broad visual acceptance. A native timeline gate holds a real draw pending while both owners are released, then verifies complete retirement. New post work preserves explicit resource-context backpressure; the verification caller polls it with its existing bounded deadline rather than forcing synchronous engine waits.

All four native renderer graphs pass **8/8 CTest entries**, including fourteen public offline compiler cases. Thirty-six affected actual Clang consumer analyses and three disabled-shader analyses are clean. The renderer-without-shaders configuration separately builds/passes **7/7**, reporting unavailable post support rather than linking a compiler. CPU 4/4, asset 9/9 and PowerShell process boundaries pass; these are not Windows native execution. All produce the expected error/exit 1 without unexpected validation/sanitizer/leak diagnostics or partial-construction destruction errors.

The compiled pipelines are lazily prepared once; callers warm them before the measured play loop. The existing 64 records, two contexts and 256 MiB VMA admission limit remain unchanged; pipeline/driver allocations are not mislabeled VMA bytes. Tiny readbacks are correctness controls, not displayed-pixel or frame-time evidence. No new dependency, source-asset change, detector suppression, capability enablement or protected-branch merge is included.
