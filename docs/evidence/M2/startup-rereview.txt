**One concrete residual defect found (P2): rejection diagnostics can report the wrong device limitation.**

- **Location:** `engine/render/context.cpp:145–147`, in the queue-family loop.
- **Trigger:** A device has a graphics/presentation family but lacks `dynamicRendering`; a later transfer-only family fails the graphics check.
- **Result:** Each family overwrites `reason`, so the final device report says `missing graphics queue`, discarding the actual device-wide feature failure. The same overwrite can hide `VK_KHR_swapchain` rejection behind a later family’s queue limitation.
- **Repair direction:** Preserve device-wide failures separately from queue-family suitability, or report family-indexed reasons. Add a multi-family regression case. Device acceptance remains correctly rejected in this example; the defect is misleading diagnostics.
