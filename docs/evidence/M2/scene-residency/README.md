# Owning checked-scene GPU preparation

Candidate runtime preparation/publication on signed `0a7fc3b`, not PBR drawing or M2 acceptance. `SceneUpload` prepares a checked package on the Context owner thread, retains its owning CPU pin, submits bounded geometry/mip phases through Context and publishes a const `SceneVersion` only after all completion checks. Worker jobs copy the CPU package pin; GPU values remain owner-thread borrowed access/release. There is no glTF/PNG/KTX/compiler linkage or source URI lookup in this runtime library.

Real public Reds establish missing geometry upload, missing image/mip upload and failure to admit a replacement while the actual ship is pinned. Native Greens verify every uploaded vertex/index and all **89,478,480 mip bytes** from the canonical package, retaining 1,304,323 vertices, 3,309,060 LOD indices, four images and all 612 CPU light definitions. Shared independent package fixtures preserve the existing reader controls. Cancellation before work and while a real timeline gate holds submitted work returns no partial version, preserves the active pin and retains/reclaims submitted staging/geometry correctly. Separate completed versions have distinct native buffers; all borrowed handles invalidate after Context close while CPU metadata remains owned.

The original 256 MiB admission cap rejected the real two-version workload. The explicit public cap is now **512 MiB**, still separate from the declared whole-graphics 1 GiB target and WSI/driver allocations. No geometry/light/texture reduction hides that failure. Two complete pinned frigate versions measure **374,669,680 VMA allocation bytes**, with **376,766,832 reserved bytes** in this workload. One bounded staging allocation also fits admission. This is not total physical GPU residency or final play-loop memory/performance evidence. New buffer/image requirement controls exceed the current cap and reject before any corresponding native object allocation. The 64-record/two-context limits remain unchanged.

Clang Debug/Release/ASan+UBSan+leak and GCC native combined graphs pass **9/9 CTest entries** plus actual synthetic/full-frigate upload, cancellation, complete readback and close checks. Six affected consumers in three actual Clang databases are clean. GCC's established clang-tidy argument limitation is not relabeled a pass. Combined scene presets/lock reuse existing renderer, runtime Zlib and offline shader pins; offline importer/cooker dependencies are absent. CI now builds this combined renderer/checked-package path, without pretending hosted CTest runs a physical scene probe.

The source/canonical package stay ignored and unchanged. No scene draw, light-selection quality, descriptor/frame pinning, shadow/transparent/IBL/UI schedule, Windows run, frame-time target or independent/human acceptance is claimed. The next work is the production scene draw and owning frame snapshot. `native-commands.txt`, `review.txt`, normalized logs, artifact/source hashes and the current-limit preflight control retain verification scope. Earlier 256 MiB evidence remains source-time evidence, not proof of the new threshold.
