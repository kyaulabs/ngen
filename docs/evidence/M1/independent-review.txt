## Actionable findings

### 1. Medium — PR commit-policy check normally validates only an ignored merge commit
**Location:** `.github/workflows/cpu.yml:32`

```sh
commitlint --from HEAD~1 --to HEAD
```

On `pull_request`, checkout normally selects GitHub’s synthetic merge commit. This range selects that merge commit rather than the PR’s commits. Commitlint’s default ignores include ordinary merge messages, and `commitlint.config.js` does not disable those ignores.

**Reproduction by reasoning:** Open a PR containing a nonconventional commit message. On the synthetic merge checkout, the configured range includes only the generated merge message; the invalid source commit is not checked. On a multi-commit push, the same command checks only the last commit.

**Consequence:** The “commit policy checks” step can succeed without validating the commits introduced by the change.

**Repair direction:** Select an event-appropriate range: PR base/head SHAs for pull requests and the before/after range for pushes. Verify the lane rejects an intentionally invalid commit in that range.

### 2. Medium — Whitespace check does not examine committed PR changes
**Location:** `.github/workflows/cpu.yml:53–57`

```sh
git diff --check
```

Without revision arguments, this checks unstaged changes against the index. A clean checkout has none; the preceding build writes ignored build outputs rather than modifying tracked source.

**Reproduction by reasoning:** Commit trailing whitespace in an owned source file and run this command from its clean checkout. It produces no whitespace finding because the defect is already committed.

**Consequence:** This step does not enforce whitespace policy on the proposed change.

**Repair direction:** Check the event’s actual base/head diff. Demonstrate failure using committed trailing whitespace, not an uncommitted working-tree edit.

## Source assessment

The inspected implementation is consistent with its deliberately narrow contracts:

- Entity, command and job storage have explicit fixed bounds and visible exhaustion errors.
- Entity reuse advances generations; exhausted generations retire slots rather than wrapping.
- Job dependencies can reference only earlier submissions, preventing cycles within the admitted graph.
- Shutdown requests cancellation before draining; borrowed callback contexts are cleared after completion. Cancellation remains cooperative, requiring finite callbacks.
- Simulation updates a staged entity copy and publishes only after successful batch processing. Overflow discards the batch without advancing published state or tick; sequence consumption matches ADR 0006.
- Snapshots own their pose storage. Their spans remain borrowed views: callers must retain the snapshot, as the recorded contract states.
- The CMake target graph and Conan requirements show no graphics, database or network-service dependency in the CPU path.

I found no concrete violation of these contracts through source tracing. That is not proof of all scheduler interleavings or borrowing usage.
