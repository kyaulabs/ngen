# C2-B validated creator edits

The default MCP launcher still exposes only project discovery and metadata. A separate `--allow-edits` launch grants preview and commit for a manifest rename, fixed `main.cpp` replacement, and a scene entity edit. The CLI uses the same operations. Each operation checks an expected revision and publishes a single file by atomic replacement. Diffs contain a name change, a source line span, or entity IDs; no source text or GLB metadata is returned.

The tests use real local stdio, SDK 2.3.0, protocol mode `2026-07-28`, and Python 3.14.10 on Linux. `PYTHONDONTWRITEBYTECODE=1 <mcp-venv>/bin/python -m unittest tests.creator_mcp tests.creator_project tests.release_automation -q` ran 35 cases: 32 passed, including all five MCP cases; three creator integration cases requiring built asset/play tools were skipped by that invocation. With the existing local asset SDK/cooker build, `NGEN_PLAY_SANDBOX_TEST=1 ctest --test-dir build/c1-project/fixed-release -R '^creator_project$' --no-tests=error --output-on-failure` passed all 11 CLI cases, including archive build/cook and both isolated play cases. All seven headless CTests and the installed Python dependency check passed. The new scene and fixed-file contract tests failed on missing tools before implementation.

The stdio test exercised read-only denial, empty-scene preview without file creation, apply and stale retry, CLI agreement, and an older open descriptor continuing to read the original source after replacement. Malformed JSON, duplicate entity keys, large decoded strings and large UTF-8 payloads, an extra path field, wrong handle, directory-lock contention, traversal references, symlinks and a hard-linked source were rejected. A real embedded GLB containing prompt-shaped metadata was admitted as data; metadata was not returned and the second project's source was unchanged. The existing CLI failure test retained the last scene on a failed save.

Defensive review led to locking CLI snapshot collection as well as edits. As documented in the [MCP guide](../../creator-mcp.md), the application bounds decoded fields, not SDK framing. The launcher and users with direct workspace access are trusted. Owner-only atomic replacement is not a power-loss durability guarantee. No builds, playtests, asset writes, cross-project access or active snapshot writes were enabled.
