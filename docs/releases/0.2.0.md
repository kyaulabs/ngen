## ✨ Highlights

NGEN 0.2.0 is the first **source release with a creator SDK and a standalone
starter project**. It also adds checked split coordinates and native tick-barrier
origin transfers. These new features warrant a minor bump from 0.1.1. This is
not a playable game download, a scene editor, or the full astronomical travel
milestone.

## 🚀 Features and fixes

- Install the opt-in static CMake SDK and build a separate C++20 project against
  `NGEN::core`, `NGEN::jobs`, or `NGEN::simulation`. Optional `Renderer` and
  `Assets` components resolve their dependencies only when requested.
- Use `tools/project.py` to create, validate, and package a standalone Linux
  starter. Cook its public board-marker asset with the existing offline tools,
  then build and run the headless test against the installed SDK. Validation and
  packaging do not execute project code.
- Install SDK configuration only in the installed prefix, not the producer's
  build root. Use a fresh producer directory when upgrading a C1-A checkout.
- Use checked split positions without flattening galactic coordinates to a
  single absolute double. Translate one existing Jolt domain between ticks
  without replacing bodies, changing velocities, or widening the single-box cap.
- Follow the verified issue-by-issue order. Scene editing and versioned saves
  are next, followed by presentation continuity, warp and streaming. The local
  MCP server, economy, and multiplayer are not part of this release.

## 🛠️ Get started

The CPU-only harness needs no GPU, display, account, service, or private scene.
The first dependency build needs network access. The primary profile uses Linux
x86-64, Clang 23.1.4, Python 3.11+, Conan 2.34.0, CMake 4.4.5, and Ninja 1.13.2.
Install the compiler and native tools through your platform. Hosted Clang 18
checks are a separate compatibility lane, not a replacement for this profile.

Download the source archive and its `.sha256` into a fresh directory:

```sh
sha256sum -c ngen-0.2.0-source.tar.gz.sha256
tar -xzf ngen-0.2.0-source.tar.gz
cd ngen-0.2.0

python3 -m venv .venv
. .venv/bin/activate
python -m pip install 'conan==2.34.0' 'cmake==4.4.5' 'ninja==1.13.2'
clang++ --version  # Must report the required primary compiler version.

sh tools/prepare.sh release
cmake --preset release -DNGEN_INSTALL_SDK=ON
cmake --build --preset release
ctest --preset release --output-on-failure --no-tests=error
./build/release/sim_harness
cmake --install build/release --prefix "$PWD/build/sdk-headless"
```

For a Git checkout, use the same setup and build commands after:

```sh
git clone --branch v0.2.0 --depth 1 https://github.com/kyaulabs/ngen.git
cd ngen
```

The starter needs a separate asset build with the `Assets` SDK component and
matching cooker tools. Follow the starter walkthrough below for `new`, `validate`,
cook, configure, build, test, run, and `package` commands. Use matching locked
compiler and dependency settings for SDK consumers. No portable binary ABI is
promised, and the SDK does not install external dependency packages.

For graphical flight, build the `demo-release` profile separately and provide a
compatible cooked scene you are authorized to use:

```sh
sh tools/prepare.sh demo-release
cmake --preset demo-release
cmake --build --preset demo-release
ctest --preset demo-release --output-on-failure
./build/demo-release/flight_demo /absolute/path/to/your-scene.ngas
```

That path needs a supported Vulkan desktop device and driver, Vulkan development
files, and the Linux desktop Pulse path. The private flight scene is not supplied.
No optional recorder SDK is required. No Windows SDK or binary package is claimed.

## ✅ Validation and limits

The reviewed [develop baseline `d34f094`](https://github.com/kyaulabs/ngen/commit/d34f094f22f434b9d74215083a2d1f6ea9d67fbb)
passed [all four CPU jobs](https://github.com/kyaulabs/ngen/actions/runs/44243238418).
External SDK installs and the standalone archive-to-cook/build/test/run path
passed their native Linux checks. The physics cases ran 10,000 live transfers
per hull size (10 m, 100 m, and a two-section 1 km proxy) against no-transfer
controls. Contact states matched each tick; position, tether length and velocity
differences stayed within the approved fixture tolerances. This does not verify
arbitrary contact scenes, prediction/render history, or inter-system travel.

Earlier Clang 18 lifetime-analysis failures on the physics topic are retained;
the revised native shape ownership passed without suppressing analysis. M3's
hardware and private preview results remain tied to their original revisions.
Publishing requires exact main-merge CI and verification of all draft downloads.
Prior tags and payloads stay unchanged.
