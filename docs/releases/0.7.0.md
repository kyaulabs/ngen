## ✨ Highlights

NGEN 0.7.0 adds an optional Linux headless board playtest. Start from a saved scene, inspect the active snapshot, save an edit or undo in another shell, then reload without restarting the player. Failed cooks and stale reload requests leave the active snapshot unchanged. With identical marker geometry, the same four saved positions required one native cook instead of four. That count measures avoided work, not end-to-end latency.

The player runs one simulation tick per accepted scene, not a continuous game or graphical editor. It never runs project code. The default CPU build and runtime SDK do not require the play tools.

## 🛠️ Get started

From a fresh directory containing the source archive and checksum:

```sh
sha256sum -c ngen-0.7.0-source.tar.gz.sha256
tar -xzf ngen-0.7.0-source.tar.gz
cd ngen-0.7.0
```

Or clone the tagged source:

```sh
git clone --branch v0.7.0 --depth 1 https://github.com/kyaulabs/ngen.git
cd ngen
```

The primary profile needs Linux x86-64, Clang 23.1.4, Python 3.11+, Conan 2.34.0, CMake 4.4.5, Ninja 1.13.2 and standard native build tools. Initial dependency preparation needs network access. The CPU harness needs no window, GPU or account.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install 'conan==2.34.0' 'cmake==4.4.5' 'ninja==1.13.2'
clang++ --version
sh tools/prepare.sh release
cmake --preset release -DNGEN_INSTALL_SDK=ON
cmake --build --preset release
ctest --preset release --output-on-failure --no-tests=error
./build/release/sim_harness
```

For play, follow the [board playtest guide](https://github.com/kyaulabs/ngen/blob/v0.7.0/docs/creator-play.md). It requires the optional asset tools, trusted executable paths, `/usr/bin/bwrap` and Linux user/network namespaces. There is no unsandboxed fallback. The fixture accepts one embedded asset and an X-only translation with unit scale and identity rotation.
