## ✨ Highlights

NGEN 0.20.2 fixes an exit error when the flight window closes during an interrupted Vulkan presentation. Recordings and save format are unchanged.

## 🚀 Features and fixes

The flight demo now waits for its newest GPU resource submission, not just the last successfully queued presentation. A skipped acquire or out-of-date present can leave a newer mesh in flight, including before the first presented frame. Shutdown drains those resources before checking run completion.

## 📦 Downloads

## 🛠️ Get started

```sh
sha256sum -c ngen-0.20.2-source.tar.gz.sha256
tar -xzf ngen-0.20.2-source.tar.gz
cd ngen-0.20.2
```

Follow the [windowed voyage guide](https://github.com/kyaulabs/ngen/blob/v0.20.2/docs/evidence/M5/windowed-voyage.md) for optional Lua, compatible cooked inputs and the owner recording command. Existing private saves can be reopened.

## ✅ Verification

A local Vulkan fixture reproduced the warning with a delayed timeline, an out-of-date acquire and a close. The fixed build passed injected close before the first present, after a later skipped acquire, and after an out-of-date present with submitted work. No Vulkan validation errors were reported in those runs. The native recorder still finishes on ordinary close and at its time limit. This fix does not establish M5 owner acceptance.
