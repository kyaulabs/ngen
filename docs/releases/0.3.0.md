## ✨ Highlights

NGEN 0.3.0 adds **scene authoring and versioned saves** to the Linux standalone
project CLI. This is a minor release for new functionality; the SDK and
unmodified 0.2.0 starter projects retain their existing workflow.

- Add, replace or remove entities with transforms, perspective cameras, point
  lights, material overrides and embedded GLB references.
- Reload saved scenes and use bounded undo/redo across CLI invocations. Each
  write checks the expected revision and saves atomically. Invalid edits, stale
  requests and failed writes leave the previous scene intact.
- Package the active scene and its current source references without local
  undo/redo history. The original five-file package is unchanged for projects
  with no saved scene.

The authored document is not a cooked package. This release does not render the
new components, add a graphical editor, or provide live play/reload, MCP, warp,
streaming, or multiplayer. Those remain separate checkpoints.

## 🛠️ Get started

Download the source tarball and its checksum into a fresh directory:

```sh
sha256sum -c ngen-0.3.0-source.tar.gz.sha256
tar -xzf ngen-0.3.0-source.tar.gz
cd ngen-0.3.0
```

Or clone the reviewed tag:

```sh
git clone --branch v0.3.0 --depth 1 https://github.com/kyaulabs/ngen.git
cd ngen
```

To try authoring without compiling NGEN, use Linux and Python 3.11+:

```sh
workspace=$(mktemp -d)
python3 tools/project.py new "$workspace/board" --name board-scene
python3 tools/project.py scene edit "$workspace/board" --expect 0 <<'JSON'
{"board":{"transform":{"position_m":[0,0,0],"rotation_xyzw":[0,0,0,1],"scale":[1,1,1]},"asset":"marker.glb"}}
JSON
python3 tools/project.py scene show "$workspace/board"
python3 tools/project.py package "$workspace/board" --output "$workspace/board.tar.gz"
```

The [scene walkthrough](https://github.com/kyaulabs/ngen/blob/v0.3.0/docs/creator-scene.md)
shows cameras, lights, materials, undo/redo, validation and the exact limits.

To build the existing CPU harness or install the source SDK, the primary profile
requires Linux x86-64, Clang 23.1.4, Python 3.11+, Conan 2.34.0, CMake 4.4.5,
Ninja 1.13.2 and standard native build tools. A cold dependency build needs
network access; the harness itself needs no GPU, window, account or service.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install 'conan==2.34.0' 'cmake==4.4.5' 'ninja==1.13.2'
clang++ --version  # Confirm the primary compiler version.
sh tools/prepare.sh release
cmake --preset release -DNGEN_INSTALL_SDK=ON
cmake --build --preset release
ctest --preset release --output-on-failure --no-tests=error
./build/release/sim_harness
```

Use the starter walkthrough for the separate `asset-release` build and cooker.
The graphical flight demo still needs the `demo-release` build, supported Vulkan
hardware/drivers and desktop audio, and a separately obtained compatible cooked
scene. No private scene is included. The
[graphical build instructions](https://github.com/kyaulabs/ngen/blob/v0.3.0/docs/releases/0.2.0.md)
remain applicable from the current checkout. No Windows SDK/binary or portable
ABI is claimed.
