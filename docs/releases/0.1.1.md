## ✨ Highlights

NGEN 0.1.1 is a **source-only documentation and roadmap patch** after 0.1.0.
It replaces the inherited template README with real NGEN startup/documentation,
records the owner-selected PvPvE/ownership and creator/MCP direction, and links
the synchronized backlog. Runtime C++ sources, shaders and supplied asset bytes
are unchanged. Version/changelog/release metadata changes do not add gameplay.

The existing 0.1.0 tag and public assets remain immutable. There is no runtime,
save-game or ABI compatibility promise beyond the recorded source evidence.
Private flight scenes, bundles and recordings are still excluded.

## 🚀 Changes

- Supplied theme-aware NGEN README branding, correct badges, pinned source startup
  and a clear distinction between working engine foundations and future features.
- Protected-space crime and overwhelming NPC punishment, lawful defense/legal
  combat, protected starts and a greatly larger lawless region replace the former
  event-only PvP plan. Protection is punitive, not invulnerability.
- Planned durable station/planet/moon/sector titles and resource/access rights,
  with lawless sovereignty and non-overridable protected NPC jurisdiction.
- Mandatory parallel C1 reusable 3D SDK/project/scene/tool/documentation milestones
  and C2 local MCP authoring, authorized builds/tests and owned playtests.
- Proposed ADR 0018 separates validated creator operations from flagship rules,
  unrestricted host access and production administration.
- Actual tracker synchronization: twelve open undated milestones, 67 open
  unassigned issues and 67 unique Todo cards. Existing identities/metadata remain;
  editor issue #55 becomes C1-D rather than a duplicate task.

These are **planning/documentation changes**. Policing, sovereignty, a creator SDK,
a general scene editor and an MCP server are not implemented in 0.1.1. M4 travel,
new gameplay/economy, Lua, multiplayer, PostgreSQL and distributed regions remain
future work. The accepted 0.1.0 CPU/render/physics/flight foundation is retained.

## 📦 Downloads

This release distributes **source only**. There are no public Linux/Windows runtime
bundles, packaged private ship/scene assets, recordings or desktop installers.
GitHub's automatic source links are distinct from the explicitly verified payload.

| File | Purpose |
|---|---|
| `ngen-0.1.1-source.tar.gz` | Versioned source, build/recipe inputs, public documentation and notices |
| `ngen-0.1.1-source.tar.gz.sha256` | SHA-256 checksum for the source archive |
| `ngen-0.1.1-SHA256SUMS` | Complete release-payload checksum inventory |

Checksums detect corruption; they are not independent publisher signatures. The
annotated source tag points to the reviewed release merge but is not independently
GPG-signed by the workflow. Published payloads are never overwritten on retry.

## 🛠️ Get started

Start with the CPU-only harness; it needs no GPU, window, account, service or
private scene. The first dependency build needs network access.

The primary profile requires **Linux x86-64, Clang 23.1.4, Python 3.11+,
Conan 2.34.0, CMake 4.4.5 and Ninja 1.13.2**, plus Git, a compatible C++ standard
library and the native build tools required by the Conan recipes. Install the
required compiler through your platform. An arbitrary system `clang` is not the
pinned profile; hosted Clang 18 compatibility evidence is a separate lane.

Download the source archive and its `.sha256` into a new directory:

```sh
sha256sum -c ngen-0.1.1-source.tar.gz.sha256
tar -xzf ngen-0.1.1-source.tar.gz
cd ngen-0.1.1

python3 -m venv .venv
. .venv/bin/activate
python -m pip install 'conan==2.34.0' 'cmake==4.4.5' 'ninja==1.13.2'
clang++ --version  # Must report the required primary compiler version.

sh tools/prepare.sh release
cmake --preset release
cmake --build --preset release
ctest --preset release --output-on-failure
./build/release/sim_harness
```

For a Git checkout, use the same setup/build commands after:

```sh
git clone --branch v0.1.1 --depth 1 https://github.com/kyaulabs/ngen.git
cd ngen
```

The graphical flight application is a separate build:

```sh
sh tools/prepare.sh demo-release
cmake --preset demo-release
cmake --build --preset demo-release
ctest --preset demo-release --output-on-failure
# A separately authorized compatible cooked scene is required; it is NOT a release download.
./build/demo-release/flight_demo /absolute/path/to/your-scene.ngas
```

Graphical execution needs supported desktop/Vulkan hardware/drivers, compatible
Vulkan development files for the build and the existing desktop Pulse audio path
on Linux. The public source does not contain the approved private scene. No
Qt/KPipeWire recorder SDK is required by NGEN; the recorder is optional host tooling.
Use fresh source/build directories when upgrading and retain local assets separately.
Windows scripted compiler/build paths exist, but no Windows binary is distributed.

## ⚠️ Compatibility and limitations

This patch does not rerun or relabel M3's hardware/private-media acceptance. Existing
Windows MSVC/ClangCl and Linux GCC evidence retains its own revision/configuration;
Vulkan 1.3 remains the graphics baseline. No portable binary ABI, reproducible build,
continuous-peak memory or arbitrary-path sanitizer claim is made.

The initial private recording's 3,854-call observation remains untraced/non-benchmark;
earlier active-desktop GUI failures remain retained. The unchanged full suite's
isolated Wayland pass and later eight scripted-reset allocations do not explain
those earlier observations. See the source-bound evidence, not a new binary claim.

## 🔒 Security and licensing

Offline startup needs no account/token/service. Private assets, recordings and
credentials are not release payloads. Existing AGPL and dependency notices remain;
commercial typefaces retain separate redistribution permissions, not automatic
AGPL relicensing or a proprietary-game exception.
