## ✨ Highlights

NGEN 0.1.0 is the initial source release after the accepted M3 offline flight
milestone. It establishes the reusable CPU/render/flight foundation and its
source/build contracts; it is not a public playable-game binary distribution.
This initial 0.1.0 baseline has no previous published version to migrate from.
The private owner-approved flight scene and recordings are deliberately excluded.

## 🚀 Features and fixes

- Bounded C++20 CPU jobs, fixed ticks, strong IDs/units, ordered commands and owning snapshots.
- SDL/Vulkan/VMA presentation, cooked asset loading, offline Slang shaders,
  PBR/IBL/shadows, instancing, post-processing and a development inspector.
- Double-position Jolt local physics, tactical/direct assisted flight,
  momentum-preserving mode changes, authored cameras and physical 32-jet RCS.
- Original bounded stereo audio with existing desktop Pulse output on Linux;
  no direct hardware fallback or account/network dependency in offline startup.
- Minimal floating HUD, on-demand controls/data/numeric performance panels,
  and owner-approved Visual Identity 1.4 surfaces and separately licensed typefaces.
- Source-bound private delivery tooling; source-only release publication with
  verified checksums, immutable published assets and reviewed back-merge PRs.

M4 astronomical coordinates/travel, gameplay/economy, Lua, network authority,
PostgreSQL and distributed regions are future work, not delivered features.

## 📦 Downloads

This release distributes **source only**. There are no public Linux/Windows runtime
bundles, packaged private ship/scene assets, recordings or desktop installers.
GitHub's automatic source links are distinct from the explicitly verified payload.

| File | Purpose |
|---|---|
| `ngen-0.1.0-source.tar.gz` | Versioned source, build/recipe inputs, public documentation and notices |
| `ngen-0.1.0-source.tar.gz.sha256` | SHA-256 checksum for the source archive |
| `ngen-0.1.0-SHA256SUMS` | Complete release-payload checksum inventory |

Checksums detect corruption; they are not independent publisher signatures. The
annotated source tag points to the reviewed release merge but is not independently
GPG-signed by the publication workflow. Published payloads are not overwritten on retry.

## 🛠️ Get started

Start with the CPU-only harness; it needs no GPU, window, account or private scene.
Building dependencies needs network access on the first run. Runtime offline support
does not mean a cold dependency build can download packages without a connection.

The primary source-build profile is **Linux x86-64, Clang 23.1.4, Python 3.11+,
Conan 2.34.0, CMake 4.4.5 and Ninja 1.13.2**, with a compatible C++ standard library,
Git and the native build tools required by the declared Conan recipes. Install the
required Clang toolchain using your platform's supported method; an arbitrary
system `clang` version is not the pinned primary profile. CI's Clang 18 compatibility
lane is separate evidence, not a promise that `tools/prepare.sh` accepts Clang 18.

Download the source archive and `.sha256` from this release into a new directory:

```sh
sha256sum -c ngen-0.1.0-source.tar.gz.sha256
tar -xzf ngen-0.1.0-source.tar.gz
cd ngen-0.1.0

python3 -m venv .venv
. .venv/bin/activate
python -m pip install 'conan==2.34.0' 'cmake==4.4.5' 'ninja==1.13.2'
clang++ --version  # Must report the required primary compiler version.

sh tools/prepare.sh release
cmake --preset release
cmake --build --preset release
ctest --preset release --output-on-failure
./build/release/sim_harness
```

For a Git checkout instead, use the same setup/build commands after:

```sh
git clone --branch v0.1.0 --depth 1 https://github.com/kyaulabs/ngen.git
cd ngen
```

To build the graphical flight application on the primary Linux setup:

```sh
sh tools/prepare.sh demo-release
cmake --preset demo-release
cmake --build --preset demo-release
ctest --preset demo-release --output-on-failure
# Supply your separately authorized compatible cooked scene; it is NOT a release download.
./build/demo-release/flight_demo /absolute/path/to/your-scene.ngas
```

Graphical execution additionally needs a supported desktop/Vulkan device and driver,
compatible Vulkan development files for the build, and the existing desktop Pulse
service for audio. Do not substitute private archived binaries or assume public
source includes the approved private flight scene. No Qt/KPipeWire recorder SDK is
required to build or run NGEN; that recorder is optional host development tooling.

Use a fresh source/build directory when upgrading, retain local assets separately,
and rebuild the selected profile. No save-game compatibility or system-wide installer
is promised. Windows compiler checks and scripted build paths are described in the
linked infrastructure guide; this source release includes no Windows binary package.

## ⚠️ Compatibility and limitations

The public source builds do not include the privately supplied ship/cooked flight
scene, Linux/Windows runtime bundles or media. The primary development profile is
Linux x86-64/Clang; separate Windows MSVC/ClangCl and Linux GCC evidence retains its
actual configuration and revision rather than promising arbitrary platform ABI.
Vulkan 1.3 is the baseline; a working compatible device/driver is still required.

The initial private recording's 3,854-call observation remains untraced and is not
clean steady-state allocation evidence. Earlier active-desktop GUI failures remain
retained; the unchanged full suite passed on an owned isolated Wayland display.
Later native diagnostics resolved eight walkthrough calls to explicit physics resets,
not the original outlier. Historical SDK/allocation and driver caveats remain in the
evidence. No reproducible-build, continuous-peak memory, sample-accurate AV or
unexercised-path sanitizer claim is made.

## 🔒 Security and licensing

No account, token or service is required by the offline harness. Private assets,
recordings and credentials are not release payloads. The repository's AGPL and
third-party source/notice obligations remain; supplied commercial typefaces retain
separate redistribution permissions and are not relicensed as AGPL. Review the
included licenses before redistributing a modified build or its assets.

## ✅ Validation

M3 acceptance and its normal integration are recorded at `03b76c72`; exact post-merge
CI passed all four jobs. The 1.4 stage records 108 CTests across four native graphs,
15 actual-command Clang analyses, strict sanitizer consumers, zero-warm-call hover
fixtures and the unchanged 20-method GUI suite on an owned isolated display.
Earlier Windows/laptop timing and sampled-memory checks retain their own revisions.

Release automation additionally requires reviewed source/version/notes checks,
offline failure/retry/security tests, exact-main-merge CI and download verification
of all three draft assets before publication. The annotated `v0.1.0` tag identifies
the exact release merge; its source archive retains that commit identity. The
workflow opens a bot-authored back-merge PR for separate review—publication does
not itself mean that back-merge is completed. Source-only publication does not
rerun or relabel old hardware evidence as a new binary matrix.
